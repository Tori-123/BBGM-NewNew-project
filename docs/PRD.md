# BBGM Scoop PRD（第一版）

依据：`README.md`。仓库内无 `docs/1-2` 或独立可行性结论；Won't 与 README「明确不做」对齐。登录方式、先审后发等开放问题在本 PRD 给出第一版默认，便于工程实现，不代表学校 SSO 已对接。

默认决策（可被后续 1.2 推翻）：

- 账号：站点自建注册 / 登录（邮箱 + 密码）；不接校园 SSO。
- 角色：注册默认为 `student`；`ADMIN_EMAIL` 匹配的账号为 `admin`；`admin` 可把已注册用户设为 / 取消 `editor`。
- 发帖：身份绑定，发布即公开，不先审后发。`student` 只能在 Community 发主帖与跟帖；`editor` / `admin` 可发 News / Sports / Dorm Life / Events，并可将 Community 帖复制精选到四栏。
- 活动：活动是带时间与地点的四栏帖，不是另一套 CMS。Community 帖不是活动。

---

## 1. Overview & Audience

**目标：** 让在校学生登录后发帖（讨论或宿舍 / 体育 / 其他大型活动），并让同学按栏目在站点上读到这些内容。

**受众：** 同一所学校的在校学生（读者、发帖者、学生活动组织者）。

**成功标准（可观察）：**

- 一名学生完成注册并登录后，能在 Community 发布主帖；另一未登录会话打开 Community 与详情，能看到同一条内容，并能阅读楼层与楼中楼。
- 一名编辑（或管理员）能向 News / Sports / Dorm Life / Events 发帖或活动帖；学生向四栏发帖被拒绝。
- 编辑可将一条 Community 帖复制为四栏新帖；原帖仍在 Community。
- 服务进程重启后，上述账号、帖与评论仍在，不依赖浏览器本地缓存作为唯一存储。
- 未登录用户不能发帖或跟帖；错误密码、缺字段、无权限操作均有明确失败结果，且不写出脏数据。

## 2. Personas & Core User Stories

最多三个画像。**第一版主故事：P1-US1（登录发帖并被同学按栏目看见）。**

### P1 发帖学生

校园里想把事发出来的普通学生，不是编辑。

- **P1-US1（主故事）：** 作为已注册学生，我想登录后在 Community 写标题和正文并发布，以便同学能在 Community 读到我的帖并跟帖。
- **P1-US2：** 作为已登录学生，我想打开「我的帖子」看到自己发过的内容，以便确认已经发出去、能再点进详情。
- **P1-US3：** 作为已登录学生，我想在校验失败时看到具体原因并留在编辑页，以便改完再发，而不是以为发出去了。
- **P1-US4：** 作为已登录学生，我想在 Community 详情跟一楼或回某一楼（楼中楼），以便讨论留在该帖下面。
- **P1-US5：** 作为已登录学生，我想选一个自带头像或上传自己的照片，以便同学在讨论里认出我。
- **P1-US6：** 作为已登录学生，我想在 Community 发帖时附上现场照片，以便同学在卡片和详情里看到图，而不是只读文字。

### P2 校园读者

想知道宿舍、体育和大型活动正在发生什么，不一定发帖。

- **P2-US1：** 作为访客或学生，我想不登录就浏览首页、四栏、Community 列表及帖子详情与楼中楼，以便先读到内容。
- **P2-US2：** 作为读者，我想从导航进入某一栏目只看该栏目帖子，以便把校报四栏和 Community 讨论分开找。

### P3 活动组织者

办宿舍活动、比赛或其他大型活动的人；须由管理员授予 `editor`（或本人是 `admin`）。与 P1 同一账号体系。

- **P3-US1：** 作为编辑，我想向四栏发帖并标明活动时间与地点，以便同学在 Events 或对应栏目里判断去不去。
- **P3-US2：** 作为编辑，我想活动帖在栏目列表里能看出时间与地点，以便不用点进每一篇才知道是不是活动。
- **P3-US3：** 作为编辑，我想把一条 Community 讨论复制成四栏稿（可改标题、正文、栏目），以便校报露出精选内容而原帖仍在 Community。
- **P3-US4：** 作为管理员，我想在用户列表里授予或取消他人的编辑身份，以便控制谁能发四栏。

## 3. Key Features（MoSCoW）

Must 服务主故事 P1-US1（Community 发帖被看见）以及角色、跟帖、四栏编辑发帖与精选所必需的部分。

### Must Have

| ID | 能力 | 说明 |
| --- | --- | --- |
| M1 | 注册、登录、退出 | 邮箱 + 密码；会话可跨请求识别当前用户。发帖回路离开登录不成立。 |
| M2 | 鉴权与权限 | 未登录可读已发布内容与 Community 评论；仅登录用户可发帖 / 跟帖；`student` 不能发四栏；用户不能改删帖或评论。 |
| M3 | 多页面 | 至少：首页、四栏列表、Community、帖子详情（Community 含楼中楼）、登录/注册、我的帖子、管理员用户列表。发帖在对应栏目页内，无独立 Submit 页。 |
| M4 | 发帖 | 标题、正文、栏目必填；发布后状态为 `published`，作者绑定当前用户。`student` 栏目只能是 `community`。 |
| M5 | 活动字段 | `editor` / `admin` 发四栏时可标记为活动；活动必须有开始时间与地点。Community 帖 `is_activity` 必须为 false。 |
| M6 | 按栏目阅读 | 栏目页只列出该栏目已发布帖；详情页展示全文、作者展示名、时间、栏目；活动另展示时间与地点。 |
| M7 | 首页露出 | 首页能进入各栏目，并展示近期**四栏**已发布帖（含活动），不含未精选的 Community 帖。 |
| M8 | 持久化 | 用户（含角色）、会话、帖子、评论、活动字段写入应用存储；重启后仍可登录并读到已发帖与评论。 |
| M9 | 关键错误处理 | 密码错误、未登录发帖/跟帖、缺必填、非法栏目、无权限、存储失败：均返回明确失败，不创建半截已发布帖或评论。 |
| M10 | 写操作留痕 | 发帖或精选复制成功时记录 `author_id`、`created_at`；服务端另写一条审计记录（谁、何时、创建了哪篇帖）。 |
| M11 | Community | 与 Sports / Dorm Life 平级的单一讨论区；一个列表，不是用户自建多吧。 |
| M12 | 楼层与楼中楼 | 仅 Community 详情：楼层 + 一层楼中楼。未登录可读；登录可写。四栏详情不加评论。 |
| M13 | 角色 | `student` / `editor` / `admin`。`ADMIN_EMAIL` 在注册或登录时升为 `admin`。 |
| M14 | 精选复制 | `editor` / `admin` 将 Community 帖复制为四栏新帖，可改标题/正文/栏目；源帖不变。 |
| M15 | 管理员用户列表 | `admin` 查看用户并授予或取消 `editor`；不能用此接口提拔或改动 `admin`。 |
| M16 | 头像 | 自带预设（`preset:oak` 等）或上传一张图；出现在顶栏、Community 帖/楼、栏目内发帖表。四栏没有封面图字段。 |
| M17 | Community 卡片 | `/community` 每条显示作者头像、标题、作者、前 4 条楼层预览；有图时露出 `images[0]`。点标题进详情看全部楼层与楼中楼。四栏列表仍用原印刷行。 |
| M18 | Community 配图 | Community 主帖作者可上传最多 4 张 jpeg/png/webp（每张 ≤2MB），存在 `images[]`。四栏帖与精选复制出的新帖 `images` 恒为 `[]`。跟帖不传图。 |

## 4. Acceptance Criteria

按主故事及使其成立的读写路径书写。格式：给定…当…则…。

### 4.1 主路径成功（P1-US1 + P2 看见 + P3 活动）

1. 给定未注册访客在注册页，当填写未被占用的邮箱与符合规则的密码并提交，则创建用户且可立即用该邮箱密码登录。
2. 给定已注册用户在登录页，当提交正确邮箱与密码，则进入已登录态，并可以在 Community 点 Write 发帖。
3. 给定已登录学生在 Community，当填写标题、正文并发布，则该帖 `published`，`category=community`，作者为当前用户，并出现在 Community 列表。
4. 给定 3 中刚发布的帖，当另一未登录会话打开 Community，则列表中出现该标题；打开详情则正文一致；首页无 `category` 的列表**不**出现该 Community 帖。
5. 给定编辑或管理员发活动帖，当标记为活动、栏目为 `events`（或体育 / 宿舍活动栏目）、填写开始时间与地点并发布，则栏目列表与详情均展示开始时间与地点。
6. 给定已发布帖已写入存储，当重启应用进程后再次打开详情 URL 并用原账号登录，则帖仍在且原账号仍能登录。
7. 给定已登录用户，当打开「我的帖子」，则能看到自己已发布的标题并进入详情。

### 4.2 校验失败 / 权限不足 / 存储不可用

8. 给定登录页，当邮箱不存在或密码错误，则登录失败、不建立已登录会话，并提示凭据无效（不提示「仅密码错误」与「仅用户不存在」的区别亦可，但不得登录成功）。
9. 给定未登录访客，当直接请求发帖或提交发帖接口，则拒绝创建帖子，并要求登录（跳转登录或等价错误）。
10. 给定已登录用户，当标题为空、正文为空、未选栏目、或栏目不在允许集合内，则拒绝发布，停留在可编辑状态，已有输入不丢（刷新导致丢失除外），存储中不出现该条 `published` 帖。
11. 给定已登录用户发活动帖，当标记为活动但缺少开始时间或地点，则拒绝发布。
12. 给定用户 A 的已发布帖，当用户 B 已登录并尝试修改或删除该帖，则失败且帖内容不变。
13. 给定发帖请求已通过校验，当存储写入失败，则向用户返回失败、不展示「发布成功」，且列表中不出现该帖。
18. 给定已登录学生，当向 `news` / `dorm_life` / `sports` / `events` 发帖，则 `403 forbidden`，存储中不出现该帖。
19. 给定 Community 帖，当未登录读取评论则成功；当未登录跟帖则 `401`，不落评论。
20. 给定已登录用户在 Community 详情，当发表楼层或回复某一楼，则该帖下可见；回复不能再套一层。
21. 给定编辑或管理员，当精选一条 Community 帖到四栏，则可改标题/正文/栏目并得到新帖 URL；源帖仍在 Community。
22. 给定管理员打开用户列表，当把一名学生设为编辑或取消编辑，则对方角色更新；学生调用管理员接口则 `403`。
23. 给定四栏详情页，当请求该帖的评论接口，则 `422`，页面不展示楼中楼。
24. 给定已登录学生在 Community 发帖并附上合法图片，当发布成功，则详情与 Community 卡片能读到同一组 `images`；向四栏帖上传图片则失败且四栏 `images` 仍为 `[]`。

### 4.3 关键非功能（可测、且为本产品需要）

14. **浏览器：** 在桌面 Chrome、Safari、Firefox 或 Edge 的近两个大版本中，4.1 的步骤 2–5 均能完成。第一版不验收 IE、原生 App、小程序。
15. **延迟：** 在本地或校园网常规条件下，栏目列表与帖子详情的 HTML 首屏（不含第三方嵌入）在 3 秒内可阅读正文或列表标题。不把未接入的图床 / CDN 超时算进本条失败，除非图片是正文唯一内容。
16. **量级：** 第一版按单校站点验收：至少支持 50 个已登录会话并存、栏目列表 100 篇已发布帖时仍能完成打开列表与详情。不做全校秒杀、不做跨校多租户。
17. **持久化：** 验收环境不得以「只写前端内存、刷新即丢」通过 4.1 步骤 6。

不验收：断网伪装演示、假数据路演模式、推荐算法效果。

## 5. Entity Flow

### 5.1 系统边界

```
访客 / 学生浏览器
        │
        ▼
BBGM Scoop 应用（Web 页面 + 服务端）
        │
        ▼
应用存储（用户、会话或等价凭证、帖子、评论、审计记录）
```

第一版 **无必须第三方**。Spotify 等不在边界内。学校 SSO / 邮箱网关未对接。

### 5.2 核心实体

| 实体 | 关键字段 | 生命周期 |
| --- | --- | --- |
| User | id, email, password_hash, display_name, role, avatar, created_at | 注册为 `student`，默认头像 `preset:oak`；可改预设或上传 |
| Session | 可校验的登录凭证，绑定 user_id，可失效 | 登录创建 → 退出或过期销毁 |
| Post | id, author_id, title, body, category, is_activity, starts_at, location, status, images, created_at, updated_at | 校验通过后直接 `published`；Community 可有 `images`；Should 才有 `hidden` / 作者删除 |
| Comment | id, post_id, author_id, parent_id, body, created_at | 仅 Community；`parent_id` 空为楼层，非空为该楼的楼中楼 |
| AuditEvent | id, actor_id, action, post_id, at | 发帖或精选复制成功时追加；只增不改 |

`category` 枚举：`news`、`dorm_life`、`sports`、`events`、`community`。无 `category` 的列表只含前四栏。

`status` 第一版：`published`。Should 增加 `hidden`。

活动不是独立聚合根：`is_activity = true` 时 `starts_at`、`location` 必填，否则为空。

### 5.3 读写关系

```
User 1 ─── * Post
User 1 ─── * Session
User 1 ─── * Comment
User 1 ─── * AuditEvent（作为 actor）
Post 1 ─── * Comment
Post 1 ─── * AuditEvent
Comment 1 ─── * Comment（楼中楼，parent 必须是楼层）
```

| 动作 | 读 | 写 |
| --- | --- | --- |
| 注册 | User（查邮箱唯一） | User |
| 登录 | User | Session（匹配 `ADMIN_EMAIL` 时升 `admin`） |
| 退出 | Session | 删除或作废 Session |
| 浏览首页 / 四栏 / Community / 详情 | Post（`published`）；Community 详情另读 Comment | 无 |
| 学生发帖 | User（当前会话） | Post（仅 `community`）、AuditEvent |
| 编辑发四栏 / 精选 | User | Post、AuditEvent |
| 跟帖 | User、Post（须 Community） | Comment |
| 我的帖子 | Post where author = 当前用户 | 无 |
| 管理员改角色 | User 列表 | User.role（`student` / `editor`） |

未登录：只读 `published` Post 与 Community 评论。  
`student`：写 Community 帖与评论。  
`editor` / `admin`：另写四栏帖与精选复制。  
`admin`：另改他人 `editor` 身份。  
存储失败时：上述写动作整笔失败，不出现「有详情 URL 但库中无行」或「有行无审计」的半成功（审计与帖子同一事务，或等价回滚）。
