# BBGM Scoop

主推荐：**BBGM Scoop**  
备选：Campus Board、The Desk

> 说明：对话中没有完整的 1.1 / 1.2 产出（竞品缺口、Must / Won't、依赖清单均未正式锁定）。下文只根据当前需求与 BBGM Scoop 页面稿整理，未确认项放在「开放问题」，不把猜测写成承诺。

## 一句话定位

给在校学生一个可登录的校园站点：既能像校报一样看到宿舍、体育和大型活动，也能自己发帖，把校园里正在发生的事发出来、被看见。

## 问题

- 校园信息散落在群聊、海报和口头通知里，活动（宿舍、体育、大型活动）不容易被系统看到。
- 现有校官方渠道偏单向通知，学生很难自己发帖、跟帖，缺少「知乎式」的校园讨论入口。
- 学生媒体若只有编辑发稿、没有登录投稿，普通学生进不了内容循环。
- 活动预告和日常帖子混在一起时，读者分不清「要不要去」和「值得一看」。
- 截稿式校报能做好头条，但对即时宿舍生活、比赛结果、临时活动反应慢。

## 用户

第一版面向同一所学校里的在校学生：日常刷校园新闻与活动的人，以及想发帖、投稿、宣传活动的人。页面稿中的 BBGM Student Media 也是同一批人里的内容整理者，但不是唯一作者。

- 读者：想快速知道「今天校园有什么」、宿舍和体育分别发生了什么。
- 发帖学生：有账号后能发帖，不需要先成为编辑。
- 活动组织者（学生）：需要把宿舍活动、体育赛事、大型活动放到对应栏目。
- 学生媒体成员（若沿用 Scoop 编辑流）：整理头条、精选、Photo of the Day 等，但不阻塞普通发帖。

## 解决方案（第一版）

1. **登录进站**：学生用账号进入站点，发帖和投稿绑定身份。没有登录仍可浏览公开内容；没有登录则发帖回路不成立。
2. **按栏目看校园**：首页与导航分开呈现 News、Sports、Dorm Life、Events 等，活动宣传落在宿舍 / 体育 / 其他大型活动上，而不是一个无分类信息流。
3. **学生发帖**：登录后发帖（知乎式：标题、正文、栏目），帖子进入对应栏目供同学阅读。这是第一版的核心闭环，不依赖模型或推荐算法；没有大模型产品仍成立。
4. **活动露出**：宿舍活动、体育赛事、其他大型活动在首页和 Events 中可被发现（时间、地点、简介）。不接售票或校务系统时，这一步仍成立。
5. **投稿 / 精选（可选增强）**：沿用页面稿的 Submit 与 Featured，把优质帖或稿件抬到头条。第三方嵌入（如 Track of the Day 的 Spotify）只承担「边栏点缀」；没有它，主站（浏览 + 发帖 + 活动）仍成立。

## 范围

### 第一版包含

- 学生登录与退出
- 公开浏览首页与栏目（至少覆盖 Sports、Dorm Life、Events / 其他大型活动）
- 登录后发帖（选择栏目、发布、查看自己的帖）
- 校园活动信息展示（宿舍活动、体育、其他大型活动）
- 基础导航与检索入口（与页面稿中的 Search、栏目导航对齐）

### 明确不做（建议，待 1.2 确认）

- 不做全校官方教务 / 选课 / 成绩系统
- 第一版不做知乎级推荐算法、关注社交图谱、付费专栏
- 不做原生 App、直播、票务支付
- 不把向量库、微服务、特定云厂商写进第一版承诺
- 不默认上线未评估的 AI 写作 / 审核模型

## 本地运行

复制环境变量模板（不要把填好的 `.env` 提交进仓库）：

```bash
cp .env.example .env
```

### 前端

```bash
cd frontend
npm install
npm run dev
```

浏览器打开终端提示的地址（默认 http://localhost:5173）。报头、栏目、发帖与登录已接 `http://localhost:8000/api/v1`（Cookie `credentials: 'include'`）。首页按真实列表填槽，没有帖时走空态，不读 schema 示例三条。

### 后端

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

启动前请在仓库根目录的 `.env` 里填好 `DATABASE_URL`、`SESSION_SECRET`、`FRONTEND_ORIGIN`（可先 `cp .env.example .env`）。缺 `SESSION_SECRET` 时进程会拒绝启动。

健康检查：http://localhost:8000/health 应返回 `{"status":"ok"}`。业务接口在 `/api/v1`（注册、登录、帖子列表/详情、发帖、我的帖子）。

契约测试：

```bash
cd backend
source .venv/bin/activate
pytest
```

Windows 激活虚拟环境请改用 `.venv\Scripts\activate`。
